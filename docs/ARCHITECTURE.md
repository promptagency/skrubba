## Masker interface

```ts
export type EntityType =   // maskera's labels verbatim, so placeholders match its format
  | "NAMN" | "PLATS" | "ORGANISATION" | "ADRESS"
  | "PERSONNUMMER" | "SAMORDNINGSNUMMER" | "ORGANISATIONSNUMMER"
  | "TELEFON" | "EPOST" | "POSTNUMMER" | "LAGENHETSNUMMER"
  | "BANKGIRO" | "PLUSGIRO" | "IBAN" | "KORTNUMMER" | "KONTONUMMER"
  | "IP_ADRESS" | "URL" | "JOURNALNUMMER" | "REFERENSNUMMER" | "REGNUMMER"
  | "ORD"        // manual selection or word list
  | "FÖRNAMN";   // a linked first name alone: [FÖRNAMN_n] belongs to [NAMN_n]

export interface Entity {
  id: string;            // stable within session
  value: string;         // canonical surface form
  type: EntityType;
  placeholder: string;   // "[NAMN_1]"
  occurrences: Array<{ start: number; end: number; surface: string }>;
  active: boolean;       // false = Behåll
  source: "rule" | "model" | "manual" | "wordlist";
  confidence?: number;
}

export interface Key {
  entries: Array<{ placeholder: string; value: string; type: EntityType }>;
  wordList: string[];
  createdAt: string;
  app: "skrubba";
  version: 1;
}

export interface Masker {
  init(onProgress: (p: { loaded: number; total: number }) => void): Promise<void>;
  maskRules(text: string, wordList: string[]): Entity[]; // sync, instant
  mask(text: string, wordList: string[]): Promise<Entity[]>; // + NER, merged
  applyMask(text: string, entities: Entity[]): { masked: string; key: Key };
  restore(text: string, key: Key, accepted?: ReadonlySet<string>): RestoreResult;
  loadKey(key: Key): void;   // uploaded key: placeholders reused, numbering continues after them
  reset(): void;             // Rensa allt, and Ny text in Skrubba
}
```

## Placeholder numbering

Numbering is assigned once per session per unique value and never reused. A session ends with Rensa allt, a key upload, or Ny text in Skrubba; numbering then starts again at `_1`. If the user edits the text and an entity disappears, its number is retired, not recycled. This keeps the key stable across edits.

## Merging rules and model

Priority on overlap: manual > word list > rules > model. A lower-priority span wholly inside a higher-priority one is dropped. One that partially overlaps is clipped to its uncovered part, as maskera does, so that part stays masked. Organisations from the model are active by default.

Adjacent model spans separated only by a space or an apostrophe are joined into one span ("Arc'teryx" came back as ORGANISATION + NAMN). The joined span is ORGANISATION if either part was, otherwise the first part's type.

The model can find a value in one place and miss it in another (a real case: "Norrström Media" found in a sentence, "Norrström Media AB" on the Arbetsgivare line missed). So every value the model found that starts with a capital letter and has three characters or more is also marked wherever else it occurs in the text as a whole word, genitive included, with any whitespace (a PDF line break) between its words. The spread spans rank as model spans. Lowercase and shorter values are not spread, so a stray hit like "teknik" or "AI" stays where it was found.

Swedish glues names into compound words ("Volvoavtalet", "Malmökontoret", "Fenixlanseringen"), and a whole-word match leaves those in clear text. So a value that starts with a capital letter, has four characters or more and is followed directly by a lowercase letter is masked as the start of that word: "[ORGANISATION_1]avtalet", restored as "Volvoavtalet". Manual and word-list terms of four characters or more start compounds in any case ("fenixlanseringen" too), since the user chose them: a hit in an ordinary word ("Anna" in "annan") is an over-mask they can keep. For values the model found, the capital letter is required, and only spread organisations and places start compounds, not names, since a name inside a compound is mostly a street name ("Annagatan"). A model span that covers a spread value plus such a tail is cut to the value, so "Volvoavtalet" next to "Volvo" is one company, not two. When a higher-priority span claims the start of a compound, a lowercase remainder glued to it ("kampanjen" in "Nordljuskampanjen") is dropped rather than kept as a model span of its own. Values of three characters or fewer never start compounds, so "Per" stays out of "Personal".

maskera's `regnummer` rule (ABC 123, ABC 12D) is off by default upstream because booking codes share the shape. We turn it on: a miss is worse than an over-mask, and the user can keep a false hit with one click.

Our own context rule masks NNNNNN-NNNN right after "org.nr", "orgnr" or "organisationsnummer" as ORGANISATIONSNUMMER even when the checksum fails. maskera only masks Luhn-valid org.nr.

Three more rules of our own (`contextRules.ts`) cover what the owner's real texts showed maskera and the model missing:

- **Company names.** Up to five capitalised words before a company form (AB, HB, KB, Aktiebolag, Ltd, GmbH, AS, Oy and others, optionally "(publ)") are an ORGANISATION. Only the name is masked, so the text reads "[ORGANISATION_1] AB" and the name alone elsewhere gets the same placeholder: every occurrence of the name is marked, genitive included. Common sentence openers in front ("Enligt", "Kontakta", "Bolaget") are left out of the name, and when one found name ends with another ("Tillsammans Norrström Media" and "Norrström Media"), the shorter is used. When a rule claims the name inside a model span, a leftover that is only a company form is dropped instead of getting its own placeholder.
- **Bare web addresses.** A domain without https:// or www. ("foretaget.se", with an optional path) is a URL when its top-level domain is on a short lowercase list, so "t.ex." and "rapport.pdf" stay out. The domain of any email address in the text is also masked where it stands alone, whatever its top-level domain.
- **Labelled numbers.** A number right after a label (kundnummer, avtalsnummer, ordernr, fakturanr, ärendenummer, referens, ref, medlemsnummer, anställningsnummer, bokningsnummer, försäkringsnummer, OCR-nummer, anläggnings-ID, mätpunkts-ID and similar, with an optional ":" or "#") is a REFERENSNUMMER: letters, digits, "-", "/" and "." in one token, or digit groups split by single spaces. Without a label such numbers look like amounts and dates, so unlabelled ones are left alone. The type is not called NUMMER, since "nummer 1" in an AI answer would then look like a placeholder.
- **VAT numbers.** SE + ten digits + 01, spaces and a dash allowed, as ORGANISATIONSNUMMER (it contains one, or a sole trader's personnummer).

Reference codes like "AB-1234-567" and bare eight-digit numbers have no fixed format and are not masked: a rule for them would also hit amounts and dates. Dates, prices and contract terms are left to *Egna ord* and selection.

Values are merged across surface forms: case-insensitive, trailing genitive `s` stripped for NAMN/PLATS/ORGANISATION, whitespace normalised. "Anna Berg", "anna berg" and "Anna Bergs" share one placeholder. The merge ignores type: the same value found as PLATS and as ORGANISATION ("Göteborg") is one entity, typed by the first type seen in the session.

First names are linked to full names. A single-word NAMN whose normalised form (as above) equals the first word of exactly one multi-word NAMN in the same text joins that entity: "Johan" and "Johans" get the placeholder of "Johan Lindqvist". If two or more full names share the first name ("Anna Berg", "Anna Ek"), a lone "Anna" is not linked and gets its own placeholder, because a wrong link restores the wrong person. Surnames alone are not linked in v1.

A linked first name is masked as `[FÖRNAMN_n]`, numbered like the full name's `[NAMN_n]`, so the AI can tell it is the same person and restore writes back the form that was there: "Johan Lindqvist … Johans chef" becomes "[NAMN_1] … [FÖRNAMN_1]s chef", and an answer that says "Hej [FÖRNAMN_1]" comes back as "Hej Johan" (decided 2026-10-12; before that every linked occurrence restored as the full name). The entity is still one item in the panel, and Behåll keeps both forms. Occurrences carry `firstName: true`; `applyMask` writes them with `placeholderOf()` and adds a `[FÖRNAMN_n]` row to the key with the first word of the full name. An uploaded key's `[FÖRNAMN_n]` row re-links that first name to `[NAMN_n]` instead of becoming a value of its own.

## Long texts

KB-BERT takes at most 512 tokens. The masker sends the model the text in parts (`src/engine/parts.ts`): at most 1 200 characters each, below the 480 tokens at which maskera would split on its own. A part ends at a paragraph break, else a sentence end, else between words; after a cut between words the next part starts up to 200 characters earlier, so a name across the cut is read whole, and model spans inside another are dropped when the parts are merged. A name the model finds as "Anna" at the end of one part and "Berg" at the start of the next is also rejoined by the existing span joining. Name spreading then runs over the whole text as before. `longtext.model.test.ts` checks that, with the parts, no name is missed that the whole text at once gives. Owner's decision, 2026-10-16 (spec: `docs/superpowers/specs/2026-10-16-masking-progress-design.md`).

The masker keeps one model run, for the latest text, in memory: a call for the same text joins it (Skrubba and Kopiera reuse the background run), a call for another text stops the old run at its next part (its promise rejects with an `AbortError`), a failed run is not kept, and `reset()` and `loadKey()` drop it. Progress is reported in characters after each part (`MaskOptions.onProgress`); the UI shows it after 400 ms as `status.scanning` under Din text and `action.scrubbing` on the button.

## Tolerant restore

LLMs mangle placeholders. `tolerantRestore.ts` normalises candidates before matching:

1. Strip brackets, quotes and backticks: `[NAMN_1]`, `NAMN_1`, `"NAMN_1"`.
2. Case-fold: `namn_1`, `Namn_1`.
3. Separator variants: `NAMN 1`, `NAMN-1`, `NAMN1`, `NAMN_01`.
4. Inflected or translated forms: `NAMN_1s`, `NAMN_1:s`, `NAME_1`, `PERSON_1` → map via a small alias table to the Swedish type.
5. Everything matched with rules 1–2 is restored silently. Rules 3–5 produce a **suggestion** the user confirms.

Never restore a placeholder number that does not exist in the key. Report it.

## Reading documents

A dropped or chosen file goes to `readDocument` (`src/reader/index.ts`), which starts a fresh module worker (`readerWorker.ts`), transfers the file's bytes and terminates the worker when the result arrives, on cancel and after 30 s. So a large PDF never blocks masking, a hung parser can be killed, and nothing from the file outlives the read. The UI (`FileWindow.tsx`) shows reading, then the summary and preview, and changes the pane only on "Använd texten". Owner's decision, 2026-10-14 (spec: `docs/superpowers/specs/2026-10-14-document-import-design.md`).

- **Detection** goes by the first bytes (`detect.ts`): zip (then the main part tells docx, odt, pptx and xlsx apart), OLE (`WordDocument` is doc, `__properties_version1.0` is msg, `EncryptedPackage` is a password-protected Office file), `%PDF-` in the first kilobyte, `{\rtf`. Only plain-text formats (txt, md, csv, html, eml) are told apart by name, and a NUL byte in the first 8 KiB refuses them. A renamed file is never parsed as the wrong thing.
- **Limits** (`limits.ts`): 50 MB file; zip at most 2 000 entries and 100 MB uncompressed in total; per entry at most 50 MB, at most 200:1 compression, and inflated output never past the size the zip declares (`zip.ts`, inflating with `DecompressionStream("deflate-raw")`); every byte handed out counts toward the 100 MB total, and each slide, sheet, header, footer and diagram part is read once however many times the document lists it, so a small file cannot amplify one part into gigabytes of text; compound-file sector chains checked for loops and out-of-range sectors (`cfb.ts`); 2 000 000 characters of text.
- **Text decoding** (`decode.ts`): byte order mark, then a declared charset, then UTF-8 if valid, else windows-1252, so Swedish CSV files from Excel keep å, ä and ö.
- **What is read and left out**: body text, tables (cells by tab, a row per line), text boxes, SmartArt (diagram data parts), headers, footers, footnotes and endnotes come along. Excel elements are matched by local name, so workbooks written with an `x:` prefix read too. Comments, deleted revisions, hidden text, speaker notes, hidden slides and sheets, and attachments are left out, and the result carries a note (`hiddenLeftOut`, `attachmentsLeftOut`) only when such content was present. Field instructions and metadata are never read. Emails start with Från, Till, Kopia, Ämne and Datum (`read.*` in `docs/COPY.md`), sheets with "Blad: namn", slides with "Bild n".
- **PDF** (`formats/pdf.ts`): `pdfjs-dist` 6.4.299, loaded only for the first PDF. pdf.js runs in a worker of its own, nested in the reader worker and ended with it: its worker module wires itself to any worker it is imported into (`initializeFromPort(self)`), so it cannot share the reader worker. Options: `disableFontFace`, `useSystemFonts: false`, `disableAutoFetch`, `disableStream`, `useWasm: false`, `useWorkerFetch: false`, bytes passed as `data`, no `cMapUrl`, `standardFontDataUrl` or `wasmUrl`. pdf.js 6 has no `eval` left. Lines are rebuilt from item positions (`pdfLines.ts`) and then go through the paste tidy-up (`pasteCleanup.ts`). Filled-in text and choice fields and text typed onto the page (FreeText) come along; other annotations with contents (comments) set `hiddenLeftOut`. A PDF with no text items is `noText` (scanned); a password gives `encrypted`.
- **Privacy**: the CSP is unchanged. The reader chunks and pdf.js are files of the build, served from our origin and precached by the service worker, so reading works offline (`offline.spec.ts`). `no-egress.spec.ts` reads a PDF and a Word file and asserts no request leaves the origin.
- **Known limits** (PLAN.md, Open questions): an Outlook message whose only body is compressed RTF gives the headers only; `.doc` deleted revisions are not detected and table rows come out on one line; xlsx dates come out as serial numbers.

## Privacy enforcement

- CSP meta tag, added at build time by `vite.config.ts` (the dev server needs inline scripts): `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; connect-src 'self'; worker-src 'self' blob:; img-src 'self' data:; style-src 'self'; font-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'`. `'wasm-unsafe-eval'` is required for onnxruntime to compile WASM; it does not allow JavaScript eval.
- transformers.js env: `allowRemoteModels = false`, `allowLocalModels = true`, `localModelPath = "/models/"`, `useWasmCache = false` (it would import the runtime .mjs from a blob: URL, which the CSP blocks), `backends.onnx.wasm.wasmPaths` = the plain build's .mjs and .wasm under `/runtime/`, `wasmBinary` = the unpacked wasm. `env.fetch` is wrapped so requests for packed files fetch and join the parts. The worker sha256-checks the runtime (against the generated packed-file list) and the ONNX weights (against `config.ts`) before reporting ready.
- Playwright test `no-egress.spec.ts`: records every request during a full mask → restore session and asserts all URLs share the app origin.
- Playwright test in `restore.spec.ts`: proxies `localStorage`, `sessionStorage`, `indexedDB` and `document.cookie` before the app loads, runs a full session (scrub, copy, restore, download key) and asserts none was touched and nothing was persisted, workers included.
- Service worker caches only same-origin assets. See Delivery and offline.
- Visit counting (owner's decision, 2026-10-12). `src/ui/analytics.ts` posts one page view per load to `/api/event` on our own origin, only on `skrubba.promptagency.se` and never with Do Not Track, Global Privacy Control or `navigator.webdriver`: `{ n: "pageview", u, d, r }`, with only `utm_*` kept in `u` and only origin and path in `r`. The Cloudflare Pages Function `functions/api/event.ts` accepts nothing else (400 otherwise), drops any other field, honours `DNT`/`Sec-GPC` again, and forwards the event to `https://plausible.app.promptagency.se/api/event` with the visitor's IP (`X-Forwarded-For`) and `User-Agent`, which Plausible needs to count unique visitors and does not store. So the CSP stays `connect-src 'self'`, `no-egress.spec.ts` still holds, and nothing is stored in the browser.
- Cross-origin isolation (COOP `same-origin`, COEP `require-corp`) so onnxruntime can use threads. Since every resource is same-origin, `require-corp` blocks nothing; it also stops any future cross-origin embed from slipping in unnoticed.

## Delivery and offline

First visit downloads about 53 MB: the model gzipped in two parts (48.9 MB), the runtime gzipped (3.7 MB) and the app. Cloudflare Pages caps files at 25 MiB, so anything bigger is split; `scripts/limits.ts` fails the build if a file in `public/` or `dist/` is over the cap.

Only onnxruntime-web's plain build is shipped. It loads and runs the model in Chromium, Firefox and WebKit (`tests/e2e/model.spec.ts`). Vite's copy of the asyncify build is dropped from `dist/`.

The editor is locked until the model is ready (`docs/UX.md`). To make that wait happen once:

- `src/ui/serviceWorker.ts` registers `/sw.js` (production only) and waits until it controls the page before the model worker is created, so the worker's downloads go through it.
- `sw.js` precaches the small files on install and caches each packed part the first time the app fetches it, so nothing is downloaded twice. Cache keys carry each file's content revision. On activate, entries in neither the current nor the previous build are deleted; a tab still on the previous build gets its files from the cache. Every served path except `index.html` is content-addressed (hashed assets, model folder by revision, runtime folder by onnxruntime version, packed-file list bundled into the worker), so old and new files never mix.
- A deploy reaches a returning visitor on the second load: the first finds the new `sw.js` and installs it. `/sw.js` must never be cached (`public/_headers`). `SW_KILL=1 npm run build` produces the kill switch. Covered by `tests/e2e/deploy.spec.ts`.
- When the service worker is in control, transformers.js's own model cache is off (`browserCache: false`), so the device keeps one copy of the model, not two.
- Without a service worker (private mode, blocked) the app still works; transformers.js's cache and the HTTP cache are all there is.

## Worker protocol

```
main → worker: { type: "init", browserCache }
worker → main: { type: "progress", loaded, total } ... { type: "ready" }
main → worker: { type: "ner", id, text }
worker → main: { type: "ner-result", id, spans: [{start,end,type,source:"model"}] }
worker → main: { type: "error", id?, message }
```

If the worker fails to initialise (old browser, blocked WASM), the app continues in rules-only mode and says so in the status bar. It never silently degrades.

## Routing

One path, `/`. Vanliga frågor and the kodnyckel are windows (`<dialog>`) over the app, so there is no router. The service worker answers every navigation with the app shell.

## Performance budgets

- Rules on 10 000 chars: < 50 ms main thread.
- NER on 10 000 chars after load: < 3 s. Measured about 1.4 s in Chromium with threads (`tests/e2e/perf.spec.ts`).
- First paint: < 1 s on 3G. Model loads lazily after first paint.
